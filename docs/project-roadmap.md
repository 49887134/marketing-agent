# 四节课程项目路线图

总计 4 × 60 分钟，面向有 Vue 3、TypeScript、Electron、WebSocket 基础、正在学习 Python 和 AI 应用开发的学员。

**仅第一阶段已经实现。以下第二至第四阶段均是规划，当前仓库没有 RAG、LangGraph、大模型调用、PostgreSQL、向量检索、Docker 部署等能力。**

| 阶段 | 课堂目标 | 计划产物与验收 |
| --- | --- | --- |
| 第 1 课：基础搭建（已实现） | 理解职责拆分、HTTP 联调和指标计算 | Vue 中文看板、Electron 窗口、FastAPI 模拟报表、测试、中文教学材料；可从真实 HTTP 得到筛选和汇总 |
| 第 2 课：知识库与 RAG（未实现） | 从投放知识文档检索证据后作答 | 整理 data/knowledge 文档；切分、嵌入、PostgreSQL + pgvector 检索；回答携带文档来源，无证据时明确拒答 |
| 第 3 课：Agent 与分析工具（未实现） | 用 LangGraph 组织可观察的分析流程 | 识别问题 → 选择报表工具 → 参数校验 → 执行只读查询 → 基于结果解释；复用现有报表 service；展示节点和工具状态 |
| 第 4 课：验收、部署与表达（未实现） | 以验证证据说明系统能力与边界 | 基础评测集、Docker Compose 服务编排、环境配置、故障演示、项目面试讲述 |

## 第二课：RAG

课前准备一小批经过授权、适合课堂使用的知识文档，标记来源和更新时间。课堂优先跑通少量文档的检索与引用闭环，使用预先准备的数据库环境减少安装时间。计划增加文档导入脚本、稳定的片段 ID、嵌入模型配置和检索接口；API 密钥仅在后端环境变量中配置，不进入桌面包或前端代码。

验收：一条可回答问题返回相关引用，一条无依据问题明确说明无法回答，修改知识文档后可更新索引。知识检索与精确投放数字分工明确，数值由报表接口提供。

## 第三课：LangGraph 工具调用

工具采用只读 `campaign_report`，参数与现有日期、关键词契约保持一致，禁止模型绕过校验随意拼接 SQL 或执行命令。图节点管理检索、工具执行、结果解释和异常分支；记录耗时、输入输出和失败原因。按教学时间选择简单 HTTP 或已有 WebSocket 基础展示流程状态，不强制增加通信复杂度。

验收：可追踪一次工具调用；遇到缺失日期时按明确策略处理；接口失败时不编造数据；最终解释能追溯到实际报表结果。本阶段规划也不包含真实调价。

## 第四课：基础评测与 Docker

准备约 10–15 条小型评测样例，覆盖知识命中、无证据拒答、日期筛选、工具参数错误、零分母和数字忠实性。分别记录检索相关性、引用正确性、工具选择与参数正确率、数字一致性、失败案例及响应耗时，避免仅凭展示效果评价 AI。

计划用 Docker Compose 编排 FastAPI、PostgreSQL + pgvector，并提供健康检查、数据卷和环境模板；部署浏览器静态资源。Electron 仍作为客户端，桌面安装包与后端自动打包另行安排。验收包括全新环境启动、服务健康、数据持久化和失败恢复。导师可课前准备镜像，课堂集中讲配置与验证。

## 当前与后续的明确边界

当前没有真实百度推广 API、真实调价、大模型 API、数据库、向量检索、LangGraph、微调、OCR/VLM、账号权限、桌面安装包或后端自动打包。未来真实业务接入必须另行定义授权、数据治理、只读/写入边界及操作确认机制，不能把本地教学演示直接用于生产账户。
