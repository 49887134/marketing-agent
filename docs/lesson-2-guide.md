# 第二节课教师指南：投放知识库与 RAG 问答（60 分钟）

本课流程：教师先演示与讲解 → 发代码包和单独的后端 .env → 学员共享屏幕运行 → 一起观察结果。没有第一课复盘，没有从零写功能环节，没有课后作业。保留第一课报表和 Electron。

**当前备课状态：已读取本地 backend/.env，用千帆 embedding-v1（实测 384 维）、ernie-4.5-turbo-20260402 与真实 Supabase 完成入库、重复执行、三类演示问题和 top_k 对比验证。** 当前知识库 4 文档、17 片段。课前仍需检查真实服务是否可用，使用 real 命名的截图/记录，不使用 mock 截图冒充。具体证据见 `docs/lesson-2-verification.md`。

## 课前准备（不计入 60 分钟）

1. 先看 `docs/lesson-2-run.md`，在 backend/.env 配置 Supabase、Embedding、Chat；不在共享屏幕时展示凭据。
2. 本机已初始化、入库。日常课前运行 `scripts/lesson2.ps1` 的 db-check、verify 即可；换机器需先 check/install。修改知识资料后才手动 ingest；相同资料重复执行应 `changed:false`，当前为 4 文档/17 片段。完整 PowerShell 命令见运行说明。
3. 打开 `artifacts/lesson-2-real-verification.json`，核对 `passed`、三条回答、引用原文和 top_k 对比。只有文件中的真实结果才是课前验证证据；失败时先解决，不使用 Mock 冒充成功。
4. 准备浏览器 `http://127.0.0.1:5173` 的“知识问答”、Swagger `http://127.0.0.1:8000/docs`、VS Code 源码。浏览器为课堂主线，Electron 可快速补充展示。
5. 学员提前有 Python 3.12、Node/npm、VS Code、PowerShell，并确认能访问远程数据库和模型服务。本节不装 Docker/PostgreSQL。首次依赖下载有不确定性，提前提醒预留网络时间。
6. 准备学生 ZIP，真实 backend/.env 通过私聊单独发送。学生包 README 即为操作说明，包内不含教师指南。
7. 自己先按下面顺序演练一次。若真实服务仍不可用，明确告知只能讲代码和失败状态，不能声称完成了真实 RAG 演示。

## 三类演示问题与依据

| 类别 | 直接输入 | 应核对的内容 | 当前实际验证结果 |
| --- | --- | --- | --- |
| 明确依据 | 为什么汇总 CTR 不能直接平均各行 CTR？ | `03-aggregation.md` 的“汇总 CTR 为什么不能直接平均”；总点击/总展现，原文示例 1.9%，不是 5.5% | 真实通过：回答总点击/总展现与样本权重，引用该章节的两个片段 |
| 改写表达 | 把每个计划的点击百分比加起来除以计划数，能代表整体表现吗？ | 仍应检索汇总比率资料；对照实际返回，不提前保证某个相似度分数 | 真实通过：否定简单平均，引用 CTR 定义和汇总计算章节 |
| 文档未覆盖 | 百度推广账户退款需要哪些材料、几个工作日到账？ | 四份资料未提供退款材料或时效；应提示依据不足，不能编造政策 | 真实通过：有候选资料但依据不足，status=insufficient_evidence，引用为空 |

这些问题与页面示例、`backend/app/verify_knowledge.py` 的 QUESTIONS 完全一致。本次真实记录 passed=true，三个案例均通过；后续模型输出可能变化，课前执行 verify 后以新记录为准。出现真实失败要记录问题、片段和错误 code。

## 0–8 分钟：完整效果演示（必讲）

**打开**：浏览器知识问答；必要时 Chrome Network 的 `/api/knowledge/ask`。

**0–1 分钟开场话术**：

> “今天我们给这个工作台增加知识问答。你输入问题后，系统会先从我们准备的投放资料中找相关段落，把这些段落交给模型，再展示回答和原文依据。接下来我先演示结果，然后沿着数据流讲实现，最后你在自己的电脑上运行。”

**1–4 分钟操作**：刷新状态，展示文档/片段数。点第一个示例，top_k=3，提问。等待完成后先读回答，再展开引用原文和检索片段。核对引用中的总点击/总展现和 1.9% 模拟例子。

> “这段答案不是存放在 Vue 里的固定文本。下面的原文来自数据库中的知识片段。‘检索片段’表示候选资料，‘引用依据’表示本次回答选择使用的资料，两者数量可以不同。”

**4–6 分钟操作**：点击改写示例，再提问。观察是否仍返回汇总比率章节，比较片段 ID。不要承诺分数或措辞完全相同。

> “输入没有逐字匹配文档标题，我们希望语义检索仍能找到同一主题。是否做到了，要看返回的片段，而不是只看模型写得顺不顺。”

**6–8 分钟操作**：点击退款问题。预期“资料依据不足”，无有效引用。若有相关但无答案的候选段，展开说明。

> “相关资料不一定足以回答。我们的文档没有退款材料和到账时效，因此不能生成一个看起来确定的政策。系统会提示依据不足。”

**可能被问到**：

- 为什么不用模型直接回答？——本项目要让回答依据来自可核对的投放资料；检索提供上下文，引用帮助核查。
- 有引用就一定对吗？——不一定。代码检查 ID 是否来自本次检索，不能自动证明每句话都准确，仍要看原文。

时间紧时只演示第一和第三个问题，改写问题留到最后学员环境；不挤占运行时间。

## 8–20 分钟：切分、Embedding、检索与上下文（必讲）

**打开**：`data/knowledge/03-aggregation.md` → `backend/app/services/knowledge_documents.py` 的 `load_chunks` → `backend/app/services/model_client.py` 的 `embed_texts`、`build_messages` → 页面检索片段。

**8–11 分钟，文档与切分**：打开完整文档，对比二级标题和返回片段的 section。

> “知识库的起点是我们整理的四份短文档，不是模型训练。这里先按二级标题划分主题，再按当前向量模型的输入预算切开。千帆这个模型输入上限很短，我们把完整输入控制在 360 个 UTF-8 字节内，标题也计入，并保留少量重叠。当前得到十七段，资料正文都被保留下来。这个字节预算是保守保护，不是精确 token 计数。”

解释 `document_id` 标识资料，`chunk_id` 标识片段，`source` 是相对文件路径，哈希识别内容版本。不要把字符数说成 token 数。演示哈希字段即可，不逐行讲 hashlib。

**11–14 分钟，Embedding**：定位 `embed_texts` 中 input 和返回维度检查。

> “Embedding 服务把文字转换成数字向量。文档入库时做一次，提问时再把问题转换成向量。向量相似是我们寻找相关内容的信号。生成答案使用另一个 Chat 模型，所以我们分开配置两个模型，不能假设聊天模型也会生成向量。”

说明文档与问题必须同一兼容模型、同维度；配置签名不一致时阻止查询。切换模型由教师统一重新入库，学员不要随意修改。

**14–17 分钟，向量检索**：打开 `knowledge_store.py` 的 `search_chunks`，只圈出 `OPERATOR(...<=>)`、ORDER BY、LIMIT 和阈值过滤。

> “pgvector 计算问题向量与文档向量的余弦距离，距离越小越接近。我们按距离排序，最多拿 top_k 段，再排除低于阈值的片段。页面显示的是相似度，不是答案可信度百分比。这里只有十七段，先使用精确搜索，便于理解和验证。”

**17–20 分钟，上下文与生成**：展示 `build_messages` 的 system 和 user 数据结构，不展示 .env。

> “Chat 模型接收的问题和资料在这里组织起来。每段资料都有 ID、标题、章节和正文。我们要求它只基于资料回答，并返回答案、依据是否足够、引用 ID。文档中的文字是资料，不作为系统指令执行。”

**可能被问到**：

- 为什么要切分？——整份资料可能过长且混有多个主题；按段检索便于控制上下文和定位来源。
- 为什么需要重叠？——长段在窗口边界处可能截断语义；重叠能保留一些相邻信息，也会增加重复内容。
- top_k 越大越好吗？——不保证。更多上下文可能补充信息，也可能增加无关内容、时延和费用。
- 相似度 0.8 是 80% 正确吗？——不是，没有做这样的概率校准。

余弦数学推导、近似索引算法、模型内部结构是补充，不在课堂展开。

## 20–35 分钟：沿代码讲两条流程（必讲）

### 20–26 分钟：A. 教师怎样将知识入库

按顺序打开并定位：

1. `scripts/lesson2.ps1` 的 `init`、`ingest` 分支。
2. `backend/app/knowledge_cli.py` 的 `main`。
3. `backend/app/services/knowledge.py` 的 `ingest_documents`。
4. `backend/app/services/knowledge_documents.py` 的 `load_chunks`、`corpus_hash`。
5. `backend/app/services/model_client.py` 的 `embed_texts`。
6. `backend/app/services/knowledge_store.py` 的 `initialize`、`replace_collection`。

> “这是课前由我运行的命令。init 只建立我们项目缺少的表，不重置数据库。ingest 读取文档、切分、计算内容指纹，内容没变就跳过。变化时先拿齐向量，之后才开启写入事务，替换 lesson2 集合的内容。如果向量服务失败，旧知识库保留。”

展示 `knowledge_index`、`knowledge_chunks` 两张表名和 WHERE collection 约束。

> “我们与学员共用远程 Supabase，但项目表限定在 marketing_agent。资料只需要我课前入库一次。你启动应用不会自动执行这段写库逻辑，也不需要在自己电脑装数据库。”

**操作**：优先展示课前真实 ingest 输出。若确认资料和配置未改变，可现场再次执行 ingest，预期 `changed:false`、计数不增加。不要为了演示更新临时修改共用资料。哈希相同但第一次入库未完成时，不承诺跳过。

**可能被问到**：

- 改一份文档后怎么办？——教师手动 ingest；本实现对 lesson2 全集合重算和事务替换，适合小资料集，没有实现增量 Embedding 缓存。
- 会删其他项目数据吗？——写操作只针对独立 schema 下 lesson2 集合，不重置数据库。
- 数据留在本机吗？——不。正文和向量在远程数据库，模型服务也会收到用于 Embedding 或回答的内容。

### 26–35 分钟：B. 问题如何变成带引用的回答

按请求顺序打开：

1. `frontend/src/components/KnowledgePanel.vue`：`submit`、answer/retrieval/error 状态。
2. `frontend/src/api/knowledge.ts`：`askKnowledge` → `request`，POST question/top_k。
3. `backend/app/routes/knowledge.py`：`ask`；`backend/app/rag_models.py`：`KnowledgeQuery`。
4. `backend/app/services/knowledge.py`：`answer_question` → `retrieve`。
5. `knowledge_store.py`：`ensure_compatible`、`search_chunks`；`model_client.py`：`embed_texts`。
6. `model_client.py`：`build_messages` → `generate_answer`，定位 allowed 集合和 citation_ids 校验。
7. 回到 `answer_question`：从真实检索片段中构造 citations，再到 Vue 的引用与 details 模板。

> “点击提问后，Vue 发送 question 和 top_k。FastAPI 用 Pydantic 校验长度和范围，再进入 service。service 检查索引和模型是否匹配，给问题做 Embedding，再去数据库检索。没有合适资料就直接提示不足；有资料再组织上下文调用 Chat。”

用前端/Node 概念补充：

> “FastAPI 的路由函数相当于 Express 的路由处理器；Pydantic 类既定义输入结构，也在运行时检查输入。Python 类型注解本身不等于运行时校验。service 是普通 Python 函数，集中处理业务步骤，数据库和外部模型各自有明确边界。”

> “模型输出也不直接相信。这里要求合法 JSON，且引用 ID 必须属于本次检索。最后给前端的标题和原文都从检索结果取，模型不能自己生成一个来源地址。”

**操作**：Swagger 的 `POST /api/knowledge/ask` 输入第一个问题和 top_k=3，Execute。对照 JSON 的 answer、citations、chunks 与页面三个区域。切换到 `/search`，说明它没有 Chat 调用。响应里金额/实时账户数据不在本节职责内。

**可能被问到**：

- 为什么有片段还说不足？——相似主题可能没有问题所需的具体政策或数字，由模型判断资料是否充分；判断仍可能出错。
- 为什么不直接把模型给的引用展示出来？——引用 ID 可以伪造，必须限制在此次实际检索集合内。
- 模型失败会变成空知识库吗？——不会，模型失败返回 502/504，前端显示失败和重试；资料不足是成功响应中的独立状态。

时间紧时先讲通问答主线。事务锁、SQL 参数绑定细节、CORS、Electron 隔离和取消实现作为答疑，不逐行讲。

## 35–50 分钟：学员本地启动并完成真实问答（必讲）

**打开**：学生包中的 README，学员共享 VS Code 与 PowerShell。教师不打开真实 .env 内容演示，只确认路径。

**35–38 分钟**：发送 ZIP 和单独的 backend/.env，解压到新目录，打开内层项目根目录。

> “现在你拿到的是可运行源码。请打开同时包含 backend、frontend、scripts 和 .tools 的目录，把我单独发的 .env 放到 backend。我们连接同一个远程知识库，所以你不执行初始化和入库。”

**38–44 分钟**：从根目录依次执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/lesson2.ps1 -Action check
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/lesson2.ps1 -Action install
```

预期 Python 3.12、npm 可用；脚本安装本机 venv 与 .tools Node，再安装前端依赖。看到错误时停在该步，按学生 README 处理，不连续粘贴后续命令。

> “虚拟环境要在你的电脑创建，不能复用我的 Python 路径。这个脚本同时准备项目专用 Node，因此不依赖教师电脑上的隐藏目录。”

**44–47 分钟**：终端 A 执行 `-Action backend`，终端 B 执行 `-Action frontend`。浏览器打开 `/docs` 的知识状态，再打开 5173 的知识问答。

**47–50 分钟**：学员点第一个示例并提问，展开真实引用原文。验收不是只看网页能打开：要看到一次真实回答、引用和原文对应。记录学员机是否成功，不把教师机测试写成学员机测试。

**可能被问到**：

- 解压就能直接运行吗？——还需要本机 Python、Node/npm、依赖安装、网络及有效 .env。
- 为什么不能看到我的本地文档修改？——服务读取已经入库的远程内容，本地文件修改不会自动改变共享数据库。
- 密钥放在哪里？——仅 backend/.env，前端通过本机 FastAPI 访问模型，不携带这些密钥。

**排错优先顺序**：目录/文件名 → py/npm → 依赖 → 后端 `/docs` → status.code → search → ask。安装下载慢时保留时间完成一次问答，减少前面补充讲解与参数对比。若到 50 分钟仍未启动，最后十分钟继续排错，不声称已验收，也不临时新增作业。

## 50–60 分钟：观察检索、参数对比和答疑

**50–54 分钟，必做**：在学员环境运行改写问题和退款问题，展开检索片段。对照 source、section、content，确认实际检索与引用关系。

> “我们现在看的是你本机后端访问同一个远程知识库的结果。请留意：候选资料是否相关，回答有没有超出原文，缺少政策资料时有没有明确提示不足。”

**54–57 分钟，弹性对比**：第一个问题，top_k=1 点击“仅检索”，记下片段数、第一段主题和分数；改成 3 再点击“仅检索”，比较新增片段。保留相同问题、模型、阈值，避免一次改多个条件。不要为演示临时改教师共用数据库。

> “我们只改变候选数量上限，不改知识文档。数量可能增加，也可能因为阈值保持不变。更多片段是否有用，需要看它们是否补充了回答依据，不能简单说三段一定比一段好。”

本次实际结果：top_k=1 返回汇总 CTR 章节一个片段，相似度约 0.6330；top_k=3 返回该章节两个片段及“零展现时的点击率”，约 0.6330、0.5988、0.4617。三个片段并非全部同等必要，适合现场说明增加 top_k 不保证更好。结果以当次运行界面为准。

若启动耗时较多，取消这段对比，优先保留学员完整问答和一次依据不足验证。

**57–60 分钟，总结与答疑话术**：

> “今天我们完成了文档切分、向量入库、问题检索、上下文组织和引用回答。你可以通过页面看到模型读了什么资料，也能区分资料不足和服务失败。下节课再把这套知识问答与已有报表工具组织到 Agent 工作流，本节没有引入 LangGraph 或自动调价。”

可能被问到：

- 为什么每次答案可能不一样？——生成模型仍有不确定性；temperature=0 降低随机性，不保证字面完全一致。
- 引用 ID 正确能完全消除幻觉吗？——不能，ID 校验只验证来源集合，回答内容是否忠于原文仍需评测。
- 如何判断检索问题还是生成问题？——先点“仅检索”看证据；没有合适原文先查知识/Embedding/阈值，有原文但答错再查上下文和生成模型。

## 故障恢复速查（教师补充，不逐项宣读）

| 故障 | 恢复动作 |
| --- | --- |
| 状态提示 configuration_missing | 核对 backend/.env，补配置后重启后端；不要在共享屏幕公开凭据 |
| database_unavailable | 查远程项目是否暂停、5432 网络、URL 编码和 SSL；TCP 可达不代表认证成功 |
| extension_missing / permission_denied | 教师按运行说明执行最小 SQL；学员不自行重置数据库 |
| embedding_mismatch | 恢复教师统一配置；确需换模型时课前统一重建，课堂不让学员改共享索引 |
| search 正常但 ask 失败 | 检查 Chat 服务、额度及 JSON/引用格式；允许重试，不能把失败说成资料不足 |
| frontend 连不上 | 先确认 8000 后端，再查 VITE_API_BASE_URL、端口和 CORS |
| Electron 下载失败 | 本节先用浏览器完成主线，Electron 运行时课前另行准备 |

本节不生成或布置课后作业。
